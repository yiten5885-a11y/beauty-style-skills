# 发型美学升级报告

将用户授权的正面肖像转译为一张清晰、可执行的发型提案图。核心变化只发生在发型：长度、刘海、层次、头顶蓬松度、两侧体积、发尾秩序和自然发色。默认交付一张横向 4:3 PNG，并同时给出短版结构化说明。

## 输入与身份边界

- 必须有用户授权使用的、可辨认的正面或近正面照片；照片缺失、过小、严重遮挡或滤镜过重时先要求更合适的照片。
- Image A 仅作为身份与原始发型参考。保持脸部辨识度、五官结构、脸型比例、年龄感、皮肤真实质感、表情、服装、背景和拍摄条件稳定。
- 不改变五官、脸型、肤质、妆容或服装来制造“变好”；不换脸、不磨皮、不制造虚假的 before。
- 不从照片推断性别认同、健康、性格、收入、族群或客观美丑。脸型、发量、发质等只写成“可见观察”或“低置信度推测”。

## 标准画面结构

使用干净的白色、米白或浅灰背景，少量低饱和功能色。不要让图像模型直接排版密集中文；先生成无字、身份稳定的视觉素材，再以确定性排版合成。

1. 顶部：`AI 发型美学升级报告`、`Before & After Hairstyle Upgrade Report` 和主题标签。
2. 左侧：未经优化的 `Before / 原始发型` 大图与简洁的 `Key Features` 信息栏。
3. 右侧：同一人的 `After / 主推发型` 大图，标注六个可执行观察点：刘海、头顶、两侧、层次、发尾、发色。
4. 中下部：4 个 `Best Options / 推荐方案`，每个写名称和一句优势；方案间应有差异但仍像同一个人。
5. 下方：3 个 `Less Flattering / 避雷提醒`。可以轻微幽默，但不能恶搞、丑化或使用夸张舞台发型。
6. 底部：`Hair Style Guide / 执行指南`，包括最佳发长、修剪重点、日常打理、维护周期和 3–4 个自然发色卡。

## 设计判断

- 默认优先自然、低维护、真实可剪的方向，例如轻层次、清爽侧分、自然空气感；不要自动生成杀马特、过度油头、明显漂染或舞台造型。
- 每个建议都要说明“改变什么”和“为什么适合当前可见条件”，不要用“显脸小”“高级”等空泛结论替代可执行细节。
- 维护周期、造型产品、发色和可施工性是建议，不是事实保证；不编造精确价格、耗时、发质诊断或效果承诺。
- 如果照片不足以支持脸型、发量或发质判断，标记 `不易判断`，不要强行归类；可同时提供两个候选方向。

## 生成与验收

1. 先写一份短 brief：用户目标、保持不变项、可见发型现状、拟改变项、置信度和不确定性。
2. 生成 Before 与 After 素材时使用同一张照片作为身份参考；Before 必须保持原样，After 只改发型。若身份漂移、脸部变化、服装变化或光线变化明显，丢弃该轮素材。
3. 单独生成 4 个推荐方案和 3 个避雷方案；不要把大量文字交给图像模型渲染。
4. 用确定性排版写入中文和英文标签，输出 4:3 PNG。最终图必须标注 `AI 模拟 / 视觉提案`，不可称为实拍、试剪或效果保证。
5. 以全尺寸和缩略图检查：同一人、Before 未被美化、After 只改发型、文字可读、箭头指向正确、推荐/避雷数量正确、没有私密文件名或路径。

## 不适用与失败处理

- 不用于整容、注射、激光、治疗、头皮疾病、脱发诊断、药物建议或结果预测；需要时缩小为非医疗的发型/造型提案。
- 如果图像工具不可用、无法接收参考图或持续发生身份漂移，只交付草案 brief 和未完成原因，不把提示词或空白版式称为完成品。
- 公开发布只允许公开 Skill 说明和不含真人数据的封面；原始肖像、生成的人像、个人字段和中间素材不得进入 Git 仓库。
