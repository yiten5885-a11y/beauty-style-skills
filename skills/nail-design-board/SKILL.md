# 美甲灵感设计板

把用户的主题转成一套有统一语言、又有十指节奏变化的美甲设计。默认最终交付是真实 PNG 图片，不用一段提示词或纯文字方案冒充成品。

## 输入与素材角色

至少需要一项：文字主题，或 `inspiration_reference` 灵感图。以下均为可选：`hand_reference` 手部照片、甲长、甲型、预算、避用元素、工艺偏好、佩戴场景与语言。

- 明确称呼素材角色，不使用含混的 Image A 或 Image B。
- 灵感图只用于提取颜色、情绪、构图语言、纹理和符号；其中的人物不是用户，也不是手部参考。
- 手部照片只在本次任务中作为上手预览参考；不要把照片路径、身份特征或可复原描述写入清单或日志。
- 未提供手部照片时，使用不指向真实人物的通用成年手模，并明确写为通用手模模拟；不从照片推断性别认同。
- 若现有信息足以设计，直接推进。只有缺少主题和灵感图，或用户的关键限制互相冲突时才提问。

## 标准交付

默认交付一张 2400x1800 横向 4:3 PNG，并可附结构化设计清单。成品包含：

1. 主题与灵感来源；
2. 三个主色、两个辅助色、一个点缀色；
3. 四至六个风格关键词和四至六个转译元素；
4. 左右手各五枚设计，使用固定编号 `L1`–`L5`、`R1`–`R5`；
5. 甲型、关键工艺和适用场景建议；
6. 明确标注的 AI 模拟上手图；
7. 施工、材料、价格和时长需由美甲师核实的边界说明。

编号固定为：1 拇指、2 食指、3 中指、4 无名指、5 小指。左手和右手都使用这套序号。

## 工作流

### 1. 固定简报

记录用户明确给出的主题、喜欢与避用项、甲长/甲型、预算倾向、工艺复杂度和场景。不要补造尺寸、材料成分、价格、耗时或用户偏好。

### 2. 建立设计清单

按 [清单契约](references/manifest-schema.md) 创建 JSON。先决定系列的视觉语法，再逐枚分配主视觉甲、衔接甲与留白甲。十枚可以有呼应，但不得全都相同或互不相关。

运行：

```bash
python scripts/validate_nail_manifest.py design.json
```

清单未通过时先修清单，不进入生图。

### 3. 生成两类无字视觉素材

使用能实际接收参考图的图像生成或编辑工具；把每张输入图的角色写清楚。

- 十指设计平铺图：严格两排五枚，左手 `L1`–`L5`、右手 `R1`–`R5`，无文字、无手部、无多余甲片。清单是内容真源。
- 上手预览图：优先展示十指；有手部参考时只改变指甲设计，尽量保留肤色、手型、饰品和拍摄条件；无参考时使用通用成年手模。禁止水印和图内文字。

分别生成素材，不让模型一次完成带密集中文的整张海报。若十指数量、手指结构或图案映射错误，定向重做失败素材；不要通过文字说明掩盖图像错误。

### 4. 可控排版

用排版脚本把模型生成的无字素材与确定性中文合成。优先使用当前 Codex 工作区依赖加载器返回的 Python；脚本需要 Pillow：

```bash
python scripts/render_nail_board.py design.json \
  --nail-plan nail-plan.png \
  --on-hand on-hand.png \
  --output nail-design-board.png
```

文字主题可不传 `--inspiration`；使用图片灵感时传入该参数。脚本默认输出 2400x1800，并在保存时不携带输入图片元数据。

### 5. 逐项验收

完整执行 [质量门禁](references/quality-gates.md)。至少打开最终 PNG 与两张生成素材，核对：

- 正好十枚设计，编号无缺失、重复或左右错位；
- 平铺图、文字清单和上手图是同一套设计；
- 手指数量、关节、甲片方向和遮挡合理；
- 缩小查看时标题、编号、设计名和关键边界仍可读；
- “模拟”标签可见，未把美观等同于已经制作或可施工。

## 边界与失败行为

- 这是设计灵感与沟通稿，不诊断甲病、皮肤问题或过敏，也不根据照片给治疗建议。
- 材料、价格、时长、耐久度、过敏风险和施工可行性只有在美甲师或产品规格确认后才能作为事实。
- 不声称生成图是实拍、已经制作、已经试戴、像素级保真或保证复刻。
- 不复制参考作品的签名、水印、商标或完整构图；提取抽象设计语言并形成新组合。
- 生图工具不可用、参考图未被工具实际接收、十指映射持续失败或最终图片未能打开时，标记图片交付阻塞。除非用户明确改要文字简报，否则不能把清单、提示词或排版空壳报告为完成。
- 原始手部照片、生成上手图和包含个人信息的清单不得进入公开仓库。
